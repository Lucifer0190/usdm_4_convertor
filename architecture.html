The thesis

The whole market fails the same four ways

Banting Health, MITRE ProtocolMiner (22/29), Protocol2USDM — all plateau for identical structural reasons. Each of our four core mechanisms targets one of them directly. That mapping is the design.

Why the market plateausOur counter-mechanism
Single-path extraction
One extractor per field — so its error becomes the system's error, with nothing to catch it.
→
Multi-method ensemble
Every field extracted by ≥2 independent paths. Agreement auto-accepts; disagreement routes to review.
Uncalibrated confidence
Reviewers can't see which fields are risky, so residual errors slip straight through human review.
→
Grounded verifier + calibration
A critic model checks each value against its source span; confidence is measured, so triage is surgical.
SoA rebuilt from flat text
Linearizing the PDF destroys merged cells and multilevel headers — the #1 Schedule-of-Activities failure.
→
Vision-first geometry
Grid structure read from the page image deterministically; the LLM only labels — it never reconstructs the table.
Static systems
No competitor learns from the SME's corrections — the same mistakes recur on every protocol, forever.
→
Closed-loop learning
Every correction becomes a few-shot example, then SLM training data. Un-reviewed accuracy rises per protocol.
2 paths @ ~89% agree on ~80–85% of fields → ~97–99% precision on the agreed set

The accuracy math. When two independent extractors agree, both must make the same mistake to fool the system — so precision on the agreed set jumps well above either path alone. The ~15–20% they disagree on is exactly what a human should see. The SME reviews less and catches more. We don't win with a better model — we win by measuring our own uncertainty honestly.

Assurance layer · the moat

Three mechanisms nobody else ships

Candidate entities from the extractors flow through here and come out scored and triaged. This layer is the reason the pipeline exceeds the ceiling — it is Phase-1 core, not a later nicety.

4.1 Ensemble

Two independent paths per field

Prose → Claude RAG + a second-family model. SoA → text + vision. Numeric/timing/dose → self-consistency voting (sample N, take majority) because those carry the highest clinical risk.

4.2 Verifier

A grounded critic pass

A separate call asks: “is value V supported by source span S?” — grounded in retrieved text, never memory. unsupported is forced to review regardless of agreement. The dedicated hallucination catch.

4.3 Confidence

Calibrated, not guessed

Confidence = f(agreement, verifier verdict, retrieval score, code status), calibrated on the eval set so “90%” means ~90% correct. That is what makes the review UI's triage trustworthy.

Safety-critical module

The Schedule of Activities sub-pipeline

A wrong test at a wrong time point is a protocol deviation — a GCP event. So the SoA never routes through the prose extractor. Vision reads geometry first; semantics come second.

Geometry
Multimodal model returns the grid from the page image: header hierarchy and merged-cell spans, explicitly.
Values
Cell values pulled from the layout-parsed table text — the deterministic path.
Cross-check
Reconcile vision vs text per cell: both / text-only / vision-only / none. Disagreements surfaced, never auto-resolved.
Build
Emit ScheduledActivityInstance, ISO-8601 Timing windows, Condition for footnote-gated cells, TransitionRule for cyclic logic.
Model orchestration

Claude-primary, tiered thinking, ensemble-diverse

The router picks model and thinking budget per task. A second family appears only where error independence is the point — running the same model twice is not an ensemble.

Build strategy

Fork the ecosystem — add what no one has

Two mature open-source bases give us the plumbing on day one, so our effort goes entirely into the Assurance and Learning layers that constitute the differentiator.

Extraction base

Panikos / Protocol2USDM

Already does PDF parsing, vision SoA, multi-model orchestration (Claude/Gemini/GPT), USDM v4.0 serialization. Our Foundation + Extraction baseline.

Plumbing base

data4knowledge libs

Pydantic USDM model, CDISC CORE validation wiring, Excel↔USDM, HTML render, Neo4j loader. Our Integrity + Data layers.

What we add

Assurance + Learning

Ensemble, grounded verifier, calibrated confidence, closed-loop correction capture. No competitor ships these — this is the moat.

First move · 1–2 days

The spike — ground every assumption before writing pipeline code

  1. Load CDISC DDF-RA example instances into the data4knowledge pydantic model → confirm they validate.
  2. Run the CORE engine against them locally, in Docker → confirm the gate works and violations are readable.
  3. Run Protocol2USDM on one public protocol PDF → see its raw output and exactly where it stops. That defines what Assurance must add.
  4. Stand up the docker compose skeleton — app + CORE + Neo4j placeholder.
Green light from the spike = the whole design is grounded in runnable reality. Then we build the ingest → assurance → validate spine on one protocol end-to-end, and only then scale to the 3–5 PoC protocols.
